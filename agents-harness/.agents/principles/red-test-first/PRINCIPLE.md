# 失敗するテストを先に用意してから直す

不具合は、それを再現する失敗テスト (Red) を先に用意し、失敗を確認してから修正する。修正後に同じテストが通る (Green) ことで、直ったことを示す。

## いつ適用するか

- 不具合報告を受けて修正するとき
- 回帰を見つけたとき

## すること

- 修正の前に、不具合を再現する最小のテストを書き、実行して、想定した理由で失敗することを確かめる。
- 修正して、同じテストが通ることと、既存のテストが壊れていないことを確かめる。
- 失敗するテストを、修正より前に置く (コミットを分けるなら別コミットにする)。

## しないこと

- 失敗を見ずにテストを書かない。常に通るテストは何も守らない。
- テストが書けないからと、修正だけを入れない。書けない理由 (環境・コスト) を述べ、別の再現手段 (手動の再現手順など) で代える。
- 再現テストが重い統合テストになるときは、より小さい単位に落とせないかを先に考える。
