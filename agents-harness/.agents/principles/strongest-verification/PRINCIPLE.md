# よりごまかしの効かない検証手段を選ぶ

検証手段には強さの順がある。手段が取れる範囲で強い側へ寄せる。

1. example testing: 選んだ入力に対する出力だけを確かめる。選んだ例の外は何も保証しない。
2. ADT による型検査: 不正な状態を型で表現できなくする。コンパイルが通る限り、その不変条件は破れない。
3. 形式証明・モデル検査: 状態空間全体で性質を確かめる。並行・状態遷移の問題は反例が得られる。

## いつ適用するか

- テストや検証の方針を決めるとき
- 「この状態は起きてはならない」という不変条件を扱うとき

## すること

- 不変条件はまず型で表現できないかを考える。ユニオン型・分岐の網羅検査・ブランド型で不正な組み合わせを作れなくする。
- 並行処理・状態遷移・プロトコルなど、example では網羅できない性質は、モデル検査を検討する。手順は playbook `formal-modeling` を使う。
- 弱い手段で済ませるときは、なぜ強い手段を取らないかを一言添える。

## しないこと

- 型で守れるものを、実行時のテストだけで守らない。
- 強い手段を使うこと自体を目的化しない。コストに見合わないときは、理由を述べて弱い手段にする。
