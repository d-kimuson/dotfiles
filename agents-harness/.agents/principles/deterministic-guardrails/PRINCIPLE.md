# 自然言語の指示より決定論的な仕組みで守らせる

ガイドラインに書いただけの規約は、守られたり守られなかったりする。機械が判定できるルールは、機械に強制させる。

## いつ適用するか

- 同じ指摘をレビューや対話で 2 回した、または 2 回しそうなとき
- コードの書き方、ファイル配置、依存の向きなどの規約を決めるとき

## すること

- 強制の手段を、強い順に探す。型 → linter・ast-grep のルール → テスト → CI・スクリプト・hook。
- 同じ指摘を 2 回したら、3 回目を待たずに仕組みへ移す。仕組みを入れたら、元の文章ガイドラインは削るか、仕組みへの参照だけにする。
- ルールを入れたら、違反するコードで実際に失敗することを確かめる。

## しないこと

- 静的に判定できる規約を、プロンプトや文書に書くだけで済ませない。
- 判断が要るもの (設計の良し悪しなど) を、無理にルール化しない。それは文章のガイドラインに残す。
