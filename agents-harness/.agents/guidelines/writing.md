# Writing ガイドライン

文書を書く・推敲するときのガイドライン。リポジトリに writing のガイドラインがあれば、そちらを優先する。

## 情報を削る

文書を書くうえで重要なのは網羅ではなく取捨選択である。人間の認知負荷も Agent のコンテキストも有限で、AI が生成する文書は冗長になりがちなので、いかに削るかに集中する。

### 目的・想定読者・到達経路を決めてから書く

- 万人に向けて書こうとすると、文書は網羅的で冗長になる
- 目的を決めて論旨を絞り、本筋と関係ない補足を削る
- 想定読者 (人間か Agent か、その属性) と到達経路 (検索、参照、Skill など) を決めて、書く背景情報を最小限に絞る
  - 暗黙知を共有しているチームメイト向けなら、プロダクトの補足は要らない
  - Skill として読まれる本文に「いつ使うか」「どういう Skill か」は要らない。読まれた時点で目的を持って参照されている

この 3 つを書く前に決め、構成を設計してから書く。

### 冗長な表現を削る

- 同じ内容を言い換えて繰り返さない (「要するに」「まとめると」でつないで同じ内容を書き直すなど)
- 同じ主張のセクションを重ねない

### セッションのコンテキストに引っ張られない

- 結論を導くためや Agent に背景を説明するために読み込んだコンテキストに引っ張られて、目的や論旨からずれた内容を書かない
- ユーザーの指示をそのまま文書に書き起こしがちなので、決めた目的と想定読者にとって必要な情報かを確かめてから書く
- 悪い例: Agent の勘違いを人間が「A ではない」と正したやり取りが、そのまま「A ではない」と本文に書かれる

## LLM らしい書き方を抑える

LLM が生成する文書に多いパターンは、読者の正しい理解を妨げるので抑える。

### 記法

- 並列なセクションの見出しに番号 (`### 2. `) を付けない。手順など順序のあるセクションなら付けてよい
- 区切り線 (`---`) を多用しない。セクションの区切りは見出しで表す
- 引用符を強調に使わない。引用符は他者のテキストを引用するためのもの
- 強調 (`**`) を乱用しない。1 つの文章に何度も、ほとんどの文に付けると、本当に強調したい箇所が埋もれる

### 中身のない装飾表現

論旨を深めず、「ちゃんと書いている感」だけを足す表現を書かない。次のフレーズそのものを禁止するのではなく、Slop の目印として見つけ、整理に使う。

- 「重要なのは〜である」
- 「まとめると」(言い換えているだけ)
- 「正面から〜」
- 「不可欠」「核心的」「根本的な」「非常に」「極めて」

### 造語や不自然に多用される語

- 人間は LLM ほど語のニュアンスを汲み取れないので、特に人間向けの文書では読み手に負荷のかからない語を選ぶ
- 悪い例: 「正本」。意味は通じるが、人間が自然に書くことはまれ
