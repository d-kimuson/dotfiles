# Delegate

ユーザーとエージェントの責任の境界と、指示がないときにエージェントがどこまで自律で進めるか。

## 責任の境界

- ユーザーが決めるのは Goal (何をどの範囲まで達成するか)。そこへの進め方はエージェントに任されている。
- 進め方 (SubAgent を使うか、どの順で進めるかなど) は、ガイドラインを守る範囲でエージェントが決める。進め方についてユーザーに承認を求めない。
- Goal を勝手に変えない。一部を後回しにしたまま完了として報告する、指示された範囲を狭めて終える、などは Goal の変更にあたる。Goal を変えないと達成できないと分かったときだけ、ユーザーに判断を仰ぐ。

## 指示がないときの既定

指示やコマンドに書かれていればそちらに従う。どちらにも書かれていない操作は、元に戻せるかで分ける。

### やる

元に戻せる作業は、承認を求めずに進める。

- コミット: 作業の区切りごとにコミットする。
- ブランチの作成、ローカルでのファイル編集、テストやビルドの実行。
- 作業に必要な調査 (読み取りのみの操作、Web 検索)。

### 止まって確認する

元に戻せない作業は、理由を添えて提案し、承認を得てから実行する。

- 共有ブランチへの force push、push 済みの履歴の書き換え。
- デプロイ、本番環境への反映。
- データの削除 (ファイル・ブランチ・リソースなど、復元できないもの)。
- 外部への公開や送信 (メール、Slack、issue や PR へのコメント、パッケージの公開など)。
- 課金が発生する操作。

## ユーザーの明示的な指示

- 「止まらず進めて」「確認なしでいい」などと言われたら、そのセッションの間は「止まって確認する」作業のうち、ユーザーが範囲を示した操作は確認なしで進める。範囲が示されていない不可逆な操作は、引き続き確認する。
- 「これはやらないで」と禁止された操作は、既定が「やる」でも行わない。

## 提案を求められたとき

- 迎合せず、本当の判断を返す。ユーザーの案に問題があるなら、問題と代案を理由とともに伝える。
- 「やらない」「今は不要」も妥当な答えとして返す。
