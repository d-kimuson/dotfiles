# TanStack Start

TanStack Start を使った React application 構成。SPA が必要な場合も TanStack Start の `spa` mode を選ぶ。

## Mode

Setup 時にどちらかを選ぶ。

| Mode | 用途 | Build behavior |
|------|------|----------------|
| `prerender` | SEO や初期 HTML が必要なアプリ | `/` と `/home` を pre-render する |
| `spa` | 旧 TanStack Router SPA 相当 | pre-render しない SPA shell として配信する |

Cloudflare Workers Assets で配信する場合、どちらの mode でも `notFoundHandling: 'single-page-application'` を使う。`404-page` fallback は Google crawler 等に 404 と判定されるため避ける。

## Pre-render `/` + `/home` Pattern

`prerender` mode では `/` と `/home` を分ける。

- `/` は pre-render 対象にするが、UI は描画せず body を空に近く保つ。
- `/` は hydrate 後に `/home` へ `replace` navigation する。
- `/home` が実際の top page UI を持つ。
- Cloudflare fallback は SPA なので、未 pre-render path は client routing に任せる。

この構成により、`/` の pre-render 済み HTML が他 path の fallback 時に一瞬表示されるちらつきを避けられる。

## Architecture

- **SSR なし**: TanStack Start は SPA shell と build-time pre-render のために使う。request-time SSR は使わない。
- **SPA shell**: root route は `shellComponent` を使う（`component` ではなく）。
- **データ取得**: `createServerFn` は使わず、`@tanstack/react-query` + API client（Hono RPC 等）で client-side から取得する。
- **Routing**: TanStack Router file-based routing。`app/**/page.tsx` を route file とする。

## Setup Sequence

### 1. Install Dependencies

```bash
pnpm add @tanstack/react-start @tanstack/react-router @tanstack/react-query react react-dom
pnpm add tailwindcss @tailwindcss/vite
pnpm add -D @vitejs/plugin-react @tanstack/router-plugin vite
pnpm add -D @types/react @types/react-dom
# src/web/lib/test/renderHook.tsx (and the web-hooks Vitest project) need these:
pnpm add -D @testing-library/react @testing-library/dom happy-dom
```

Tailwind is part of this pattern: the template `vite.config.ts` registers `@tailwindcss/vite` and `styles.css` imports `tailwindcss`. `shadcn-ui/` builds on top of it. If the project does not want Tailwind, remove the plugin and the import together.

pnpm may print "Agent skills awaiting approval" for `@tanstack/*` packages. Approving them (`pnpm approve`) is the user's decision; mention it, do not approve on their behalf.

Optional devtools:

```bash
pnpm add @tanstack/react-devtools @tanstack/react-router-devtools
```

### 2. Vite Configuration

Copy `vite.config.ts` and customize:

- Mode: the template is `spa` (`spa.enabled: true`, `prerender.enabled: false`). For `prerender` mode, disable `spa`, enable `prerender`, and list `/` and `/home` as the pre-rendered pages.
- `srcDirectory`: TanStack Start source root (template: `src/web`; move the `src/web/` files when changing it)
- `router.routesDirectory`: `./app`
- `router.routeToken`: `page`
- `apiServerPort`: the `/api` dev proxy target. `8787` matches `defaultPort` in `hono/`'s `src/server/server.ts` and wrangler's default; change both together.
- Cloudflare plugin as needed

### 2a. tsconfig.json

On top of `typescript-package/`'s `tsconfig.json`, add to `compilerOptions`:

```json
{
  "jsx": "react-jsx",
  "types": ["node", "vite/client"]
}
```

`vite/client` types the `../../styles.css?url` import in the root route. Keep `"dom"` in `lib`.

### 2b. Generated Route Tree

`{srcDirectory}/routeTree.gen.ts` is generated by the router plugin during `vite dev` / `vite build`, and `router.tsx` imports it. Generate it once (`pnpm build` or start `vite dev`) after adding/renaming routes, and **commit it** — do not gitignore it — so `pnpm typecheck` passes on a fresh clone and in CI without a build step. `.oxfmtrc.json` already ignores `**/*.gen.*`.

### 3. Router

Copy `{srcDirectory}/router.tsx`.

- `scrollRestoration: true`
- `defaultPreload: 'intent'`
- `defaultPreloadStaleTime: 0`

Hash history (optional, for sandboxed / unknown-subpath hosting where path routing cannot work): the SPA shell is rendered in Node at build time, where `createHashHistory()` crashes because there is no `window`. Pass it only in the browser; Start supplies its own memory history on the server:

```ts
...(typeof window === 'undefined' ? {} : { history: createHashHistory() }),
```

### 4. Root Route

Copy `{srcDirectory}/app/__root/page.tsx` and customize:

- `head()` meta tags, links, scripts
- provider/layout tree in `RootDocument`
- keep `shellComponent`
- keep `<HeadContent />` and `<Scripts />`

In `spa` mode the shell markup is prerendered at build time, so anything that depends on the client (hash-history `href`s, viewport-dependent layout) can cause a hydration mismatch. If that happens, render the app shell inside `ClientOnly` from `@tanstack/react-router` with the loading UI as fallback (`component` of the root route, not `shellComponent`):

```tsx
<ClientOnly fallback={<FullScreenLoading />}>
  <Outlet />
</ClientOnly>
```

### 5. Index and Home Routes

For `prerender` mode, copy:

- `{srcDirectory}/app/index/page.tsx`
- `{srcDirectory}/app/home/page.tsx`

For `spa` mode, `app/index/page.tsx` may contain the main UI directly instead of redirecting to `/home`.

### 6. Styles and Shared Layout

Copy `{srcDirectory}/styles.css` (just `@import 'tailwindcss';`; `shadcn-ui/` extends it) and `{srcDirectory}/shared/layout/FullScreenLoading.tsx` (the root `Suspense` fallback; it uses `<output>` rather than `role="status"` to satisfy `jsx-a11y/prefer-tag-over-role`).

Add scripts:

```json
{
  "scripts": {
    "dev:web": "vite dev",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

With `hono/` on Node, also add `dev:server` and `"dev": "run-p dev:*"` (see `hono/`).

`spa` mode build output: `dist/client/_shell.html` (the SPA shell) + `dist/client/assets/*` is what gets deployed. `dist/server/` is only used at build time to render the shell; do not deploy it.

### 7. Source Directory Structure

```text
{srcDirectory}/
  router.tsx
  routeTree.gen.ts        # Auto-generated; do not edit; commit it
  styles.css
  app/
    __root/
      page.tsx
      providers/AppProvider.tsx
    index/page.tsx        # `/` empty redirect route for prerender mode
    home/page.tsx         # real top page UI for prerender mode
  apis/                   # concrete API query/mutation hooks
  components/ui/          # shadcn/ui generated components
  lib/
    api/
      client.ts
      queryClient.ts
    test/
      renderHook.tsx
  shared/                 # cross-feature code
```

## Relative Base / Subpath Hosting (optional)

When the built SPA is served under an unknown or arbitrary path (sandboxed previews, static hosting under a subpath), set `base: './'` in `vite.config.ts`. Start then has two gaps:

- It writes `/./assets/...` (root-absolute) for `<script src>`, modulepreload links, and the inline router manifest in `_shell.html`; only the stylesheet link becomes relative. Rewrite them after the shell is rendered with an inline plugin.
- It derives the router basepath from `base` (`'./'` → `'.'`). Set `router.basepath: '/'` explicitly (combine with hash history from step 3).

```ts
import { readFile, writeFile } from 'node:fs/promises';
import { join } from 'node:path';
import { defineConfig, type Plugin } from 'vite';

// Default output of TanStack Start `spa.prerender.outputPath` ('/_shell').
const shellHtmlFile = '_shell.html';

/**
 * TanStack Start normalizes `base: './'` to `/./` for the asset URLs it writes into the
 * SPA shell (`<script src>`, modulepreload links, the inline router manifest), which are
 * root-absolute. Rewrite them to document-relative `./` after the shell is prerendered.
 */
const relativeShellAssets = (): Plugin => ({
  name: 'relative-shell-assets',
  apply: 'build',
  enforce: 'post',
  buildApp: {
    order: 'post',
    handler: async (builder) => {
      const clientEnvironment = builder.environments['client'];
      if (clientEnvironment === undefined) {
        throw new Error('client build environment not found');
      }
      const { root, build } = clientEnvironment.config;
      const shellPath = join(root, build.outDir, shellHtmlFile);
      const html = await readFile(shellPath, 'utf8');
      await writeFile(shellPath, html.replaceAll('/./', './'));
    },
  },
});

// in defineConfig: `base: './'`, `tanstackStart({ router: { basepath: '/', ... } })`,
// and add `relativeShellAssets()` after `viteReact()` in `plugins`.
```

## Cloudflare Workers Assets

When using Cloudflare Workers Assets, set SPA fallback regardless of mode in `cloudflare.config.ts` (`cloudflare-workers/`). Assets come from the Vite client build:

```ts
assets: { notFoundHandling: 'single-page-application', runWorkerFirst: ['/api/*'] },
```

## Template Files

| File | Customize |
|------|-----------|
| `vite.config.ts` | `spa` / `prerender` mode, `srcDirectory`, `apiServerPort`, plugins |
| `src/web/styles.css` | Tailwind entry; extended by `shadcn-ui/` |
| `src/web/shared/layout/FullScreenLoading.tsx` | Loading UI for the root `Suspense` fallback |
| `src/web/router.tsx` | Router options |
| `src/web/app/__root/page.tsx` | meta/links/scripts, layout/provider tree |
| `src/web/app/__root/providers/AppProvider.tsx` | common providers |
| `src/web/app/index/page.tsx` | prerender empty redirect route, or SPA top route |
| `src/web/app/home/page.tsx` | top page UI for prerender mode |
| `src/web/lib/api/queryClient.ts` | TanStack Query defaults |
| `src/web/lib/test/renderHook.tsx` | Common hook test helper with Router and QueryClient providers |
