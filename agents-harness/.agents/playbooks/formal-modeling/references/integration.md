# 手元で再現できない複数コンポーネントの連携: Quint によるモデル化

マイクロサービス、外部 SaaS、メッセージキューなど、手元で一緒に動かせないコンポーネントの連携をモデルで検証する。

## モデルへの写し方

- コンポーネントごとの状態を `var` にする
- ネットワークを、送信済みで未受信のメッセージの集合 (または列) の `var` にする
- action に、正常系の送信と受信に加えて、現実に起きる故障を入れる: 再送、重複配信、順序の入れ替え、タイムアウト、コンポーネントの停止と再起動
- 性質: 二重処理の禁止、冪等性、メッセージが止んだ状態での整合 (結果整合性) を不変条件にする

## 検証

1. [quint.md](./quint.md) の手順で `quint run` と `quint verify` を通す。
2. 反例は、実システムでなく各コンポーネントの単体テストに写す。反例のメッセージの順序と故障を、相手のコンポーネントのモックで再現する。
3. 冪等キーや outbox などの対策を入れたら、モデルにも同じ対策を入れ、反例が消えることを確かめる。

判定するコマンドは、`quint verify` と、反例を写した単体テストの 2 つ。
