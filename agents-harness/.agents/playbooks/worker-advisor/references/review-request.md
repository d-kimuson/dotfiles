# Review の依頼文

次の見出しを埋めて Reviewer に渡す。

```md
あなたは Reviewer として、Worker の変更を独立にレビューする。ファイルを変更しない。Worker の報告を信用せず、diff とコードと実行結果で判断する。

## タスクと完了条件
<Advise の依頼と同じ内容>

## 方針
<advice.md のパス>

## 変更
<diff の取り方。例: `git diff <base>` を実行して読む>

## Worker の検証結果
<指標ごとの実行コマンドと出力>

## 観点
- 完了条件を満たすか。検証手段の無い完了条件が残っていないか
- 方針に反する設計、古いやり方、アンチパターンが無いか
- 方針で設計した形式検証が実行され、モデルが実装と対応しているか
- 境界 (空・0・1 件・上限)、異常系 (入力不正・外部依存の失敗)、既存の振る舞いの回帰
- 完了条件に効かない変更が混ざっていないか

## 回答の形
結論 (承認 / 要修正) と、指摘ごとに「ファイルと行、問題、根拠、修正案、必須か任意か」
```
