# 解説動画

台本 (JSON) を書いて `scripts/video` を実行すると、ずんだもん (聞き手) と四国めたん (解説役) が掛け合う解説動画と、それを再生するプレイヤーページができる。描画は motion-kit (`@kimuson/motion-kit`)、音声は VOICEVOX で、仕組みは `scripts/` が受け持つ。Agent は台本を書くことに集中する。

以下の `references/`・`scripts/` は `~/.agents/playbooks/explainer-video/` からのパス。

Agent の仕事は **調べる → 台本を書く → 確認して生成する → 公開する** の 4 つ。途中でユーザーに確認しない。

## 作業場所

呼び出し元が作業場所を指定したらそこを使う。指定がなければスクラッチパッドの `explainer-video/<トピック>/` を使う。台本は作業場所の `main.json` に書き、補講は `supplement-<n>.json` に書く。台本 `<名前>.json` の出力は `out/<名前>/` に置かれる。

| 出力         | 中身                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| `video.mp4`  | 1280×720 / 30fps。上にスライド、左右に立ち絵、下に字幕                 |
| `index.html` | 動画、チャプター目次、再生位置に追従する字幕、出典、クレジットのページ |
| `preview/`   | `preview` が撮った PNG                                                 |

## コマンド

| コマンド                           | 内容                                               |
| ---------------------------------- | -------------------------------------------------- |
| `video validate <script>`          | 台本を検証する。契約に合わない箇所をパス付きで出す |
| `video preview <script>`           | 各シーンの最後のセリフを PNG に撮る (音声なし)     |
| `video build <script> [--crf <n>]` | 動画とプレイヤーページを作る                       |
| `video yomi <text...>`             | VOICEVOX の読み (アクセント付きカナ) を出す        |
| `video schema`                     | 台本の JSON Schema を出す                          |

前提は node、pnpm、ffmpeg。初回の実行で依存 (node_modules と Chromium) を入れる。VOICEVOX ENGINE は `VOICEVOX_URL` (既定 `http://127.0.0.1:50021`) で動いていればそれを使い、なければ `voicevox-engine` コマンドか docker で起動し、終わったら止める。音声は `~/.cache/explainer-video` にキャッシュされ、作り直しでは変えたセリフだけを合成し直す。

## 1. 調べる

調査は SubAgent に任せ、要点 (事実・用語・具体例・出典) だけを受け取る。

| トピック               | 情報源                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| 一般的な技術・概念     | 一次資料 (公式ドキュメント、提唱者の文献)                                                                      |
| 社内の業務・プロダクト | 関連リポジトリのコード・ドキュメント、社内 wiki、チャット。プロジェクトの AGENTS.md に参照先があればそれに従う |

- 社内トピックは推測で埋めない。分からない点はぼかして書かず、扱わない。
- 参照した資料は台本の `sources` に入れる。
- 秘密情報を含むファイル (`.env*` など) は読まない。

## 2. 台本を書く

`references/script.md` を読んでから書く。`video validate <script>` が通るまで直す。英字・略語・固有名詞の読みが怪しければ `video yomi` で確かめ、誤読するセリフに `yomi` を足す。

## 3. 確認して生成する

`video preview <script>` が出した PNG を全部 Read で見る。

- 見出し・表・コードが枠からはみ出していない、極端に縮んでいない
- 字幕が 2 行以内に収まっている
- 立ち絵・表情記号がスライドの文字に重なっていない

問題があれば台本側で直す (スライドの文言を短くする、項目を減らす、シーンを分ける)。直ったら `video build <script>` で本番を生成する。最後に表示されるサイズが 15 MB を超えたら `--crf 32` などで作り直す。

## 4. 公開する

Artifact ツールがあれば、`out/<名前>/` の `index.html` と `video.mp4` を公開する (Artifact ツールが読めない場所なら、スクラッチパッドにコピーしてから)。作り直したら同じ Artifact に公開し直し、同じ URL を保つ。社内情報を含む動画は、誰に共有するかをユーザーに任せる。Artifact ツールがなければ、`python3 -m http.server --directory out/<名前>` で配信して URL を渡す。

ユーザーにはリンク、動画の長さ、チャプター、出典の概要を短く伝える。

## うまくいかないとき

| 症状                                 | 対処                                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------------------- |
| 読み間違い (英字・略語・固有名詞)    | `video yomi` で読みを確かめ、そのセリフに `yomi` を足す                                 |
| エンジンが起動しない・タイムアウト   | docker が動いているか確かめる。別のターミナルでエンジンを先に起動しておけば、それを使う |
| エンジンを更新したのに声が変わらない | キャッシュが効き続けている。`~/.cache/explainer-video/tts` を消す                       |
| 動画が 15 MB を超える                | `--crf` を上げる (28 → 32)。それでも大きければシーンを削って尺を縮める                  |
| motion-kit の Diagnostic が出る      | `motion-kit` skill に従い、`npx @kimuson/motion-kit docs troubleshooting` で code を引く |
