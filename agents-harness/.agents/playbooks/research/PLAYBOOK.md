# Research

読み取りだけで行う。成果物は根拠付きの説明か推薦であり、コードの変更ではない。

- 主張ごとに根拠を付ける。ファイルパスと行番号、URL、実行結果のいずれか。Web は検索結果の要約でなく原典のページを読んで引く。
- 確かめたことと推測を区別して書く。読んだだけで実行していないものは、そう明記する。
- 質問の前提が間違っていたら、そのまま答えずに押し返す。「確かか」と問われたら、理由付きで本当の判断を答える。
- 広い調査を SubAgent に分けるときは、対象、問い、根拠付きで返す形を渡す。読み取り専用と明示する。
- 調査の後にコードの変更が続くなら、ここで止めてユーザーに返し、bug-fix などの playbook で改めて進める。

## 返答

説明を求められたときは次の構成にする。

- Overview: 結論を数行で
- Key Concepts: 理解に必要な概念と用語
- How It Works: 仕組みを、根拠を付けて順に
- Where Things Live: 関連するファイルと場所
- Gotchas: 落とし穴、例外、未確認の点

選択肢から選ぶ推薦を求められたときは、選択肢を比べる表（観点ごとのトレードオフ）を付けて、推薦とその理由を述べる。
