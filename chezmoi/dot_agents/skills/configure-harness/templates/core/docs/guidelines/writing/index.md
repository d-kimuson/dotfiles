## 原則

- 1 ドキュメントに論旨は 1 つ。網羅性より、論旨を絞ることを優先する。
- 論旨と関係の薄い補足情報を書かない。
- 同じ主張を言葉を変えて繰り返さない。
- 冗長な表現を避け、端的に書く。前置き・まとめ・「〜が重要です」のような中身のない文 (Slop) を書かない。
- コード・設定・Lint から読み取れる事実は書き写さず、パスを示す。
- 他の Markdown はリンクにせず、リポジトリルートからのパスで参照する。

## レビュー
