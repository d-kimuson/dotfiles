# Coding

全般に共通する、重視すべき基本原則。Lint など静的な手段で強制されるルールはここに書かず、チェックで出た違反を直すことで守る。

## 原則

<!-- decision: coding-principles
  決めること: コード全般で重視する設計の原則 (データの扱い、状態の表し方、関数とクラス、コメント、依存の向きなど)
  観察: 既存のコードの書き方、Lint の設定、既存のコーディング規約やコントリビューションガイド
  書き方: 1 原則 1 項目の箇条書きで書く。Lint・型検査で強制できる原則は書かず、強制できるのにされていないものは、ユーザーに伝えたうえで原則として書く。既存のコードと違う原則を新たに採るなら、ユーザーに確認したうえで書く
-->

## 失敗と例外

<!-- decision: error-handling
  決めること: 回復しうる失敗と回復しない異常をどう表し、どこで変換するか
  観察: Result 型などのライブラリ、独自のエラー型、例外の投げ方と catch の場所
  書き方: 失敗の表し方、呼び出し側での分岐の仕方、外部の例外を変換するときのルールを 1 項目ずつ書く。関係するファイルはパスで示す。方針が読み取れなければ、推測で書かずにユーザーに聞いて書く
-->

## ライブラリ

用途ごとに使うライブラリを決めている。同じ用途の関数を自前で書かない。

<!-- decision: libraries
  決めること: 用途ごとに使うライブラリと、使う場所
  観察: マニフェスト (package.json など) の依存と、コード中での使われ方。同じ用途に複数のライブラリが混在していないか
  書き方: 「用途 | ライブラリ | 使う場所」の表にする。混在していれば、どちらに寄せるかをユーザーに確認する。決まったライブラリがなければ節ごと消す
-->
