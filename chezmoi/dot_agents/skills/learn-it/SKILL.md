# learn-it

本人が知らないトピックを、本人の言葉で説明できる状態まで学ぶのを支援する。教えて終わりにせず、本人の発表から理解していない部分を探し当てて埋める。

```
1. 動画で教える → 2. 質問に答える → 3. 本人が発表する → 4. 理解の穴を探る
                     ↑                                      │
                     └──────────── 穴が見つかった ──────────┘
```

フェーズは本人の発言で切り替える。固定のターン数や説明量で進めない。本人が終了・別の話題への移動・検証の省略を求めたら、それを優先する。

## 作業場所

`${LEARN_IT_HOME:-$HOME/.local/share/learn-it}/<トピック>/` を作業場所にする。`<トピック>` はトピックを表す短い ASCII の kebab-case (例: `ddd`)。

| パス                  | 中身                       |
| --------------------- | -------------------------- |
| `notes.md`            | 学習記録                   |
| `main.json`           | 最初の動画の台本           |
| `supplement-<n>.json` | 補講の動画の台本           |
| `out/<台本名>/`       | 動画とプレイヤーページ     |

同じトピックの `notes.md` があれば再開とみなし、記録されたフェーズから続ける。

## 学習記録 (`notes.md`)

会話が途切れても続きから再開できるよう、フェーズが切り替わるたびに更新する。

- トピック、本人の目的と前提知識
- 範囲を絞って外した候補
- 理解の基準 (後述) と、基準ごとの評価・根拠になった本人の発言
- 現在のフェーズ
- 受けた質問と答えの要点
- 保留している問い

記録にない理解度や過去のやりとりを、知っているふりをして補わない。

## 1. 動画で教える

目的は、本人が中心となる概念を一通り知った状態にすること。

1. 対象のレベルや使う場面で内容が大きく変わるときだけ、目的と前提知識を聞く。聞くときは想定の答えを添えて一度にまとめる。
2. 範囲を 5〜6 分の動画 1 本に収まるまで絞る。絞って外した部分は、区切りで次の候補として示す。
3. 理解の基準を 5〜8 個決めて `notes.md` に書く。基準は用語の定義ではなく、「なぜそうなるか」「条件を変えると何が起きるか」を説明できるかで書く。台本の中心概念のシーンは基準と対応させる。
4. `references/video.md` に従って動画を作り、公開する。ずんだもんの疑問と誤解には、本人がつまずきそうな点を先回りして入れる。
5. リンクを渡し、見終わったら分からないところを何でも聞いてよいと伝える。理解の基準は見せない。見せると、発表が本人の言葉ではなく基準の読み上げになる。

## 2. 質問に答える

- 端的に答える。構造の誤解には HTML 図解を作り、合っている関係と直すべき関係を具体的に示す。
- 事実、説明のための比喩や仮定、本人の理解についての推測を区別する。不確かな事実は一次資料で確かめ、出典を短く添える。
- 質問が同じチャプターに集中し、言葉と図解で埋まらないときだけ、そこに絞った補講の動画を同じ手順で作る。
- 本人が求めない限り、理解の確認を始めない。

本人が「理解した」と示したら、発表を促す。何も見ずに、そのトピックを知らない人へ説明するつもりで、自分の言葉で話してもらう。

## 3. 本人が発表する

- Agent は聞き手に徹する。発表の途中で訂正・補足・質問をしない。本人が分けて話すなら、続きを促すだけにする。
- 本人が終わりを示したら 4 に進む。

## 4. 理解の穴を探る

1. 発表を理解の基準と照らし合わせ、基準ごとに評価して `notes.md` に書く。

   | 評価         | 状態                                               |
   | ------------ | -------------------------------------------------- |
   | 説明できた   | 因果と成り立つ条件を本人の言葉で語れた             |
   | ゆがみあり   | 因果・条件・境界のどこかが誤っている               |
   | 言葉だけ     | 用語や動画の言い回しは出たが、因果を語っていない   |
   | 抜け         | 触れていない                                       |

2. 説明できた点を短く伝え、それ以外の基準について 1〜3 問出して回答を待つ。答えや答えを漏らすヒントを同時に出さない。
   - 本人の発言を起点に問う (「〜と言っていたけど、〜の場合はどうなる？」)。
   - 理由、条件を変えたときの結果、似た概念との違い、どこまで成り立つかを問う。用語の復唱や穴埋めは問わない。
   - 動画と質疑で扱っていない例外を抜き打ちで問わない。広げるなら、広げると明示して 2 に戻る。
3. 回答の合っている箇所と食い違う箇所を分けて示す。食い違いを観測したことと、その原因の仮説を区別する。原因が複数考えられるなら、切り分ける 1 問を足す。
4. 穴が確かめられたら、その箇所だけ 2 に戻って教え、直した部分だけをもう一度本人に説明してもらう。本人が「分からない」と言ったら、問うのをやめて教える。

## 区切り

すべての基準が `説明できた` になるか、本人が終わりを求めたら区切る。

- 「今回の〇〇は説明できている」と範囲を限定して伝える。少数の回答から分野全体を習得したと認定しない。
- 残った穴と保留の問い、まだ扱っていない関連する方向を 2〜4 個示す。方向には、何が新しく分かるかを一行添える。本人が選んだら、それを新しいトピックとして 1 から始める。
- `notes.md` を最終状態に更新する。
