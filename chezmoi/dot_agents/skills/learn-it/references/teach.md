# 教える

本人を「知らない」から「概要を理解した」へ進める。

## 形式

| 形式  | 向く内容                                                   | 手順                  |
| ----- | ---------------------------------------------------------- | --------------------- |
| video | トピックの導入など、複数の概念とその関係をまとめて教える   | `references/video.md` |
| eli5  | 1 つの概念・仕組み・構造の誤解など、数枚の図で伝わるもの   | `references/eli5.md`  |

本人が形式を指定したらそれに従う。指定がなければ、教える内容の大きさで選ぶ。

## トピックを始めるとき

1. 対象のレベルや使う場面で内容が大きく変わるときだけ、目的と前提知識を聞く。聞くときは想定の答えを添えて一度にまとめる。
2. 範囲を、選んだ形式 1 本 (video なら 5〜6 分) に収まるまで絞る。外した部分は `notes.md` に候補として残す。
3. 理解の基準を決めて `notes.md` に書く。基準は用語の定義ではなく、「なぜそうなるか」「条件を変えると何が起きるか」を説明できるかで書く。中心概念の説明は基準と対応させる。
4. 作って公開する。本人がつまずきそうな点を先回りして扱う。
5. リンクを渡し、見終わったら何でも聞いてよいと一言添える。理解の基準は見せない。見せると、本人の発表が基準の読み上げになる。

## 追加で教えるとき

質問への回答 (`references/answer.md`) で言葉では足りない部分だけを扱う。理解の基準は変えない。
