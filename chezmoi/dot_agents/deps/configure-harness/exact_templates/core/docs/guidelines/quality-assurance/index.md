## QA Check

1. 変更の概要と差分から、触れる機能と、上の「探索的テストの観点」のうち当てはまるものを選ぶ。
2. `docs/guidelines/quality-assurance/exploratory-testing.md` の手順でプロダクトを起動し、選んだ観点で実際に操作して確かめる。
3. 変更が `docs/guidelines/quality-assurance/human-check-criteria.md` の基準に当てはまるかを確かめる。
4. 下の「報告」に従って報告する。

## 報告

次の項目を、出し先に合わせた書式で書く (PR や issue なら Markdown、呼び出し元に返すなら指定された形式)。

- status: 次のいずれか。
  - `approve`: 選んだ観点をすべて確かめ、問題がない。
  - `reject`: 期待と違う振る舞いがある。
  - `human-check`: 問題はないが、変更が `human-check-criteria.md` の基準に当てはまる。または、確かめられない観点が残った。
- 確かめたこと: 行った操作と観察した結果を、事実だけで 1 操作 1 項目で書く。
- reject のとき: 期待と違った振る舞いと、再現の手順。
- human-check のとき: 人に確かめてほしい観点と、エージェントで担保できなかった理由。
