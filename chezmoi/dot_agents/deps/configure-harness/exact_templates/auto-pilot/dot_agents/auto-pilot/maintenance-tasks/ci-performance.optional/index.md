# CI Performance

CI の実行時間を調べて、速くする。

## 依頼

Independent Agent に次を依頼する。

「直近の CI の実行 (`gh run list`、`gh run view --json jobs`) から、ジョブとステップごとの所要時間と、その推移を調べてください。キャッシュ、並列化、重複や不要なステップの削除など、検査の結果を変えずに速くできるものを直し、`docs/guidelines/delegate.md` の完了の定義まで進めてください。検査の範囲を狭める変更 (変更されたファイルによる実行の絞り込み、バージョンの matrix を減らす、テストを間引く) はせず、効果の見積もりを添えて提案として返してください。所要時間は CI の実行から測り、ローカルでは効果が再現しない変更 (依存のキャッシュなど) には、ローカルで測った数字ではなく何が省けるかを添えてください。CI の実行の履歴が読めなければ、変更せずにその旨を返してください。いつも失敗しているジョブがあれば、速さとは別に、失敗の原因を添えて返してください。」

## 成果物

- 速くする変更 (完了の定義に従う)。変更前後の所要時間か、何が省けるかを添える。
- 検査の範囲を狭める提案は、`docs/guidelines/backlog.md` に従ってユーザーのタスクとして起票する。
- いつも失敗しているジョブは、`docs/guidelines/backlog.md` に従って Backlog に起票する。
- 履歴が読めなかったら、`docs/guidelines/team-channel.md` に従ってユーザーに伝える。
