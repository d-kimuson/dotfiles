# Exploratory Testing

QA Check で、プロダクトをローカルで起動して実際に操作する手順。

## 起動

<!-- decision: local-startup
  決めること: ローカルでプロダクトを起動するまでの手順と、起動したことの確かめ方
  観察: package.json などの scripts、Makefile、docker-compose、.env.example、README のセットアップ手順、DB のマイグレーションとシードのコマンド、開発サーバーのポート
  書き方: 依存の準備から起動までを、コマンドを添えて 1 手順 1 項目で書く。起動を確かめる手段 (ヘルスチェックの URL、ログに出る行など) と、止め方も書く。秘密情報が要るなら、値ではなく取得元を書く。リポジトリから読み取れない手順は推測で書かずにユーザーに確かめる
-->

## 操作

<!-- decision: operate
  決めること: 起動したプロダクトを操作して振る舞いを確かめる手段
  観察: プロダクトの種類 (画面のある Web アプリ、API サーバー、CLI、ライブラリ) と、そのエントリポイント
  書き方: プロダクトの種類に合わせて、操作の手段を抽象的に書く。実行する人や環境で使えるツールは違うので、生成時に試して特定のツールに決めない。画面のある Web アプリなら「その環境で推奨されるブラウザ操作のツールで起動した URL を開き、画面を操作する。使えるものがなければ `npx agent-browser` を使う」。API だけなら「起動したサーバーに HTTP リクエストを送り、レスポンスと副作用 (DB の状態など) を確かめる」。CLI ならコマンドを実行して出力と終了コードを確かめる。種類が複数あれば種類ごとに書く
-->

## 後片付け

- 起動したプロセスを止め、作ったテスト用のデータが共有の環境に残らないようにする。
