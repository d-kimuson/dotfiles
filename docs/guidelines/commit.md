# Commit

## メッセージ

- Conventional Commits に従う。件名は `type(scope): <英語の命令形>` で書く。
- 本文は日本語で、変更の理由と影響を書く。

Good: `fix(internal): stop printing config values in dry-run output`

Bad: `chore: update` (scope がなく、何を変えたか分からない)

## ボーイスカウト

コミットの直前に、その作業中に遭遇したトラブルを振り返り、仕組みに還元する。本筋の作業ではないため、サブエージェントに委譲する。

委譲時に渡すもの:

- 作業中に起きたトラブルの列挙 (失敗したコマンドとエラー、誤っていた・不足していたドキュメント、遠回りした調査など)。トラブルがなければボーイスカウトは省略する
- 以下の判断基準

判断基準:

- **その場で直す**: 仕組み側 (ガイドライン、Lint、スクリプト、設定) を直すべき問題で、修正内容に意思決定の揺れがない (事実の誤り・情報の欠落・明らかなバグなど) もの。本筋とは別のコミットにする。
- **troubleshot に書く**: 修正に判断が必要なもの、または外部ツールの挙動など仕組み側では許容するしかなくワークアラウンドだけが必要なもの。`.agents/troubleshots/<topic>.md` に `docs/guidelines/writing/troubleshoot.md` の形式で書く。

サブエージェントには、直したもの・書いたものの一覧を返させ、その内容をユーザーへの報告に含める。
